# 智能应用开发课程笔记

## 1. LangChain 与智能应用

LangChain 是一个用于构建大语言模型应用的开发框架。它把模型调用、提示词、检索器、输出解析器和外部工具组合成可复用的处理流程。开发者可以通过 LangChain 将自然语言理解能力接入网页、命令行或业务系统。

LangChain Expression Language，简称 LCEL，是 LangChain 中组合组件的一种方式。常见写法是把提示词模板、聊天模型和输出解析器用管道操作符连接，形成一条可执行链。例如：提示词模板 | 聊天模型 | 字符串解析器。

## 2. 在线大模型与离线大模型

在线大模型通过服务商提供的 API 完成推理，本地计算机不需要下载模型权重，启动快，回答质量通常较高，但依赖网络并可能产生调用费用。使用 API Key 时不能把密钥提交到公开代码仓库。

离线大模型运行在本地计算机或本地服务器上，常见工具包括 Ollama 和 LM Studio。离线方案不依赖在线服务，数据可以留在本地，但需要下载模型，并消耗更多内存、显存和磁盘空间。

## 3. 提示词工程

提示词用于描述模型需要完成的任务、回答范围和输出格式。面向课程问答时，提示词应要求模型只使用给定资料，资料不足时明确说明，不要编造不存在的内容。

系统提示词负责设定长期角色和约束，用户提示词负责描述当前任务。提示词越具体，输出通常越稳定，但仍需要通过测试问题检查效果。

## 4. 检索增强生成 RAG

检索增强生成，英文缩写是 RAG，解决的是“模型如何利用外部资料回答问题”。典型流程包括：加载资料、切分文本、建立索引、根据问题检索相关片段、把片段和问题一起交给大模型、生成带依据的回答。

RAG 可以减少模型凭空回答的概率，但不能完全消除错误。项目应保留检索结果或引用片段，方便使用者核对答案是否有资料依据。

检索方案既可以使用向量数据库和嵌入模型，也可以使用 BM25 等关键词检索算法。BM25 不需要额外调用嵌入模型，依赖较少，适合小型课程知识库。

## 5. 智能应用评测

智能应用评测需要准备一组有代表性的问题，检查回答是否正确、是否引用了课程资料、资料不足时是否拒绝编造，以及接口异常时是否有清晰提示。

除了回答质量，还应观察响应时间、调用成本和错误率。作业演示时可以选择三个典型问题：概念解释、流程说明和应用场景分析。

## 6. API Key 与安全

在线大模型通常使用 API Key 鉴权。API Key 应通过环境变量或本地配置文件读取，并通过 .gitignore 排除真实配置文件。公开仓库中只保留不带真实密钥的 .env.example。

如果密钥意外泄露，应立即到服务商控制台撤销旧密钥并创建新密钥。不要把 API Key 写入截图、日志、README 示例或源代码。
